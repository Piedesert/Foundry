# First-Wave Portfolio Decision

## Selected portfolio

The first wave is:

1. **Deep Researcher**, using the existing `research` agent as the initial canonical implementation.
2. **News Rundown**, as a scheduled, source-backed digest built on the research pipeline.
3. **Project Planner**, as a structured planning workflow built on decomposition, dependencies, and iterative refinement.

This is a portfolio decision, not a promise to implement all three simultaneously. The goal is to validate a small set of shared primitives across different interaction modes.

## Why this combination

### Deep Researcher

Provides the foundation for:

- Source discovery and retrieval
- Citation and provenance handling
- Bounded search and termination conditions
- Confidence and uncertainty reporting
- Structured output
- Fallback behavior when sources are unavailable

It is also easy to evaluate because individual claims and citations can be inspected directly.

### News Rundown

Exercises the same research capabilities under a scheduled and repeatable workload:

- Feed or search collection
- Deduplication
- Relevance ranking
- Freshness handling
- Five-item output limits
- Scheduled delivery

It tests whether the system works when the input is generated by a workflow rather than supplied manually.

### Project Planner

Exercises a different reasoning pattern without requiring risky external writes:

- Goal clarification
- Task decomposition
- Dependency mapping
- Parallel versus sequential work
- Risks and blockers
- Next-action generation

It tests structured planning and handoffs while remaining easy for the user to review.

## Shared primitives to build once

The first wave should share these primitives rather than duplicating prompt logic:

| Primitive | Deep Researcher | News Rundown | Project Planner |
|---|---:|---:|---:|
| Structured execution envelope | Yes | Yes | Yes |
| Input validation | Yes | Yes | Yes |
| Bounded iteration or step budget | Yes | Yes | Yes |
| Explicit stop condition | Yes | Yes | Yes |
| Failure and fallback handling | Yes | Yes | Yes |
| Source provenance | Yes | Yes | Optional |
| Deduplication and ranking | Optional | Yes | Optional |
| Task decomposition | Optional | No | Yes |
| Dependency graph | Optional | No | Yes |
| Human approval | No | Delivery preference | No |
| Scheduled trigger | No | Yes | Optional |

## Initial boundaries

### Deep Researcher

- Read-only.
- No external account writes.
- No unattended browsing through authentication walls or CAPTCHAs.
- Bounded source/search budget.
- Every major claim marked as verified, unverified, or contradicted.

### News Rundown

- Read-only collection.
- No automatic posting to public channels in the first version.
- Maximum five stories per edition.
- Each story retains source URL, publication time when available, and selection rationale.
- Duplicate or near-duplicate stories should be collapsed rather than repeated.

### Project Planner

- Produces plans, not task-system mutations.
- Does not create calendar events, tickets, or reminders without approval.
- Must expose assumptions, dependencies, open questions, and blockers.
- Must distinguish a proposed plan from work that has actually been completed.

## Evaluation questions

The first wave is successful if it answers these questions:

1. Can one source-verification and structured-output pattern work across research and planning?
2. Can n8n reliably trigger, retry, and deliver a scheduled digest?
3. Are the outputs reviewable without reading the entire execution trace?
4. Do explicit step limits and stop conditions prevent drift or over-retrieval?
5. Can failures be represented as useful partial results rather than silent success?
6. Can a user provide feedback that becomes a regression scenario?
7. Is the handoff envelope sufficient for passing research context into later agents?

## Deliberately deferred

- Autonomous publishing or messaging.
- Calendar, task manager, or project tracker writes.
- Financial recommendations or trades.
- Broad Personal Assistant routing.
- Long-term memory beyond the minimum state needed for a workflow.
- Vector search or RAG infrastructure unless the first-wave evaluations show a clear need.

## Exit criteria for expanding the portfolio

Before adding higher-risk or infrastructure-heavy agents, the first wave should demonstrate:

- Stable structured outputs across repeated runs.
- Explicit source and freshness metadata.
- Tested retries and failure paths.
- Observable execution history in n8n.
- A working approval pattern, even if the first wave rarely uses it.
- At least one regression test created from real user feedback.
- Clear separation between agent reasoning, workflow orchestration, and external side effects.
